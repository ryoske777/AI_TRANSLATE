# RO 로컬라이제이션 자동 번역 도구

ChatGPT(또는 Claude) 웹 UI를 구동해 Google Sheets의 게임 텍스트를 다국어로
자동 번역하는 도구. 라그나로크 온라인(RO) 로컬라이제이션 업무용.

---

## 사용자용 — 설치 (Python 불필요)

1. **`RO_Translator.exe` 다운로드**
   [Releases](https://github.com/ryoske777/ai_translate/releases/latest) 에서
   `RO_Translator.exe` 를 받습니다. (Python 설치 필요 없음 — 더블클릭 실행)

2. **`credentials.json` 준비**
   본인 Google 서비스 계정 키 파일을 준비합니다. (보안상 exe 에 포함하지 않습니다.)
   첫 실행 시 뜨는 **설정 마법사에서 '찾아보기'로 이 파일을 선택**하면 자동으로
   프로그램 폴더에 복사됩니다. (직접 exe 옆에 두어도 됩니다.)

3. **Chrome 설치**
   도구가 Chrome 을 띄워 ChatGPT 웹을 조작합니다. Chrome 이 설치돼 있어야 합니다.

4. **`RO_Translator.exe` 실행**
   첫 실행 시 **설정 마법사**가 떠서 Chrome 경로·credentials.json·스프레드시트
   주소·기본 설정을 차례로 안내합니다. (언제든 ⚙ → 🧙 로 다시 실행 가능)

5. **스프레드시트 공유 (필수)**
   마법사/설정창에 표시되는 **서비스 계정 이메일**(`...@....iam.gserviceaccount.com`)을
   구글 스프레드시트 우상단 **[공유]** 에 붙여넣고 **편집자**로 추가하세요.
   (또는 [공유] → '링크가 있는 모든 사용자'를 '편집자'로 변경해도 됩니다.)
   이 공유가 안 되어 있으면 시트가 열리지 않습니다.

> 폴더 구성 예시
> ```
> 작업폴더\
>   ├ RO_Translator.exe      ← 다운로드
>   ├ credentials.json       ← 직접 배치(필수, 사용자 고유)
>   ├ settings.json          ← 자동 생성
>   └ prompts\               ← 자동 생성(편집 가능)
> ```

## 연속 번역 — 여러 언어를 한 번에

메인 화면 헤더의 **🗂** 버튼을 누르면 **연속 번역 설정** 창이 열립니다.
체크한 언어를 위에서부터 차례로 자동 번역합니다.

- **순서 바꾸기**: 줄 왼쪽 **⠿** 손잡이를 잡고 위아래로 끌어 놓습니다.
- **기입 열**: 언어마다 **번역 결과 열**과 **특이사항 열**을 한 쌍으로 지정합니다.
  단일 언어 작업에서 "결과 D → 특이사항 E" 였던 것이, 언어 수만큼 반복되는 구조입니다.
  `자동 배치` 버튼을 쓰면 시작 열부터 두 칸씩 나눠줍니다.
  (D 시작 → ko `D/E`, en `F/G`, zh-CN `H/I`, th `J/K`, es `L/M` …)
- **방식**: `AI 번역` 또는 `원본 복사`.
  `원본 복사` 는 ChatGPT 를 거치지 않고 입력열 값을 결과열에 그대로 복사합니다.
  원본이 한국어라 번역이 필요 없는 **ko-KR** 열을 채울 때 씁니다.
- **겹침 검사**: 시작 전에 결과열·특이사항열이 서로 겹치거나 입력열(원본/참조/
  플레이스홀더)을 침범하면 막습니다. 뒤 언어가 앞 언어의 결과를 덮어쓰는 사고를
  원천 차단합니다.

실행 중에는 설정·언어·프롬프트 창과 모드 전환이 잠깁니다(도중에 열이 바뀌면
남은 언어가 엉뚱한 열에 기입되므로). 끝나면 언어별 성공/실패 요약 창이 뜹니다.

- 한 언어에서 오류가 나도 다음 언어로 계속 진행합니다.
- **STOP** 은 현재 언어를 정리한 뒤 연속 작업 전체를 멈춥니다.
- 이미 채워진 행은 건너뛰므로, 다시 실행하면 **빈 칸만** 채워집니다.

## 용어집 (Glossary)

고유명사·아이템명·스킬명처럼 **언어마다 공식 표기가 정해진 용어**를 시트 한 탭에
모아두면, 번역할 때 자동으로 적용됩니다. 설정(⚙) → 용어집에서 탭 이름을 지정하면 켜집니다.

### 왜 필요한가

`«T: »` 마커는 이후 파이프라인이 벗겨내고 **안의 내용이 그대로 게임에 들어갑니다.**
그런데 도구는 이 내용을 모든 언어에 똑같이 복사하므로, 그냥 두면 스페인어 서비스에
한국어가 박힙니다. 용어집을 붙이면 언어별 공식 표기로 바뀝니다.

```
원본 C열 :  «T:베넘 나이프»를 장착하면 …
   ↓
es-ES    :  «T:Cuchillo Venenoso» …     (번역)
th-TH    :  «T:Venom Knife» …           (영어 유지가 공식)
de-DE    :  «T:Giftmesser» …            (번역)
```

"번역할지 영어로 둘지"가 용어집 데이터에 이미 들어있으므로 언어마다 알아서 갈립니다.

### 세 가지 방식으로 적용됩니다

1. **마커 자동 부착** (v1.8.0 추가, 기본 켜짐) — 문장 속에 그냥 들어있던
   용어집 용어를 `«T:용어»` 로 감싸서 보냅니다. 예전에 번역 돌리기 전
   손으로 하시던 '1차 마커 처리'를 대신하는 단계입니다. 감싼 뒤는 2번 경로를
   타므로 **결과열에 `«T:대상언어용어»` 로 마커가 붙어 나옵니다.**
   - **표기가 용어집과 완전히 같으면 등급(HARD/SOFT/HINT)을 보지 않고 항상
     감쌉니다** (v1.10.0). '완전히 같다' 는 셀 전체가 그 용어이거나, 문장 속에서
     앞뒤가 단어 경계인 채 표기가 같은 경우입니다 — 한국어 조사가 붙은 형태
     (`포링이`, `검으로도`, `동료들에게는`)도 같은 단어로 봅니다.
     용어집에 분명히 있는 단어가 마커 없이 그냥 직역돼 나가는 일을 막습니다.
   - **표기가 달라지는 부분 일치**(합성어 안에 파묻힌 경우 등)는 예전처럼
     HARD 등급만 감쌉니다. SOFT 는 '권장(굴절 허용)' 등급이라 그런 자리까지
     마커로 굳히면 성·수·격 변화가 막혀 스페인어·독일어·프랑스어 문장이
     어색해집니다.
   - `match_mode` 가 `exact` 인 용어는 '셀 전체가 그 용어일 때만' 이라는 뜻이므로
     문장 속 등장에는 감싸지 않습니다 (용어집에 적어 둔 범위를 넓히지 않습니다).
   - 마커가 안 붙은 용어가 있으면 **어떤 용어였는지 실행 로그 끝에 알려 줍니다.**
   - 씌운 마커는 **시트의 입력(번역대상/원본) 열에도 기입**합니다. 어떤 단어가
     잡혔는지 시트에서 바로 보이고, 다시 실행해도 같은 결과가 나옵니다(멱등).
     설정(⚙)에서 끌 수 있습니다.
   - 이미 `«T:...»` 안이거나 `{CL:n}` 코드 안인 자리는 건드리지 않습니다.
     긴 용어가 우선이고(`룬 미드가르드 왕국` 이 잡히면 그 안의 `왕국` 은 안 잡음),
     한국어 조사는 마커 바깥에 둡니다(`베넘 나이프를` → `«T:베넘 나이프»를`).
2. **플레이스홀더 확정 치환** — `«T:...»` 안의 내용이 용어집에 **통째로** 있으면
   그 언어의 용어로 바꿔 기입합니다. **AI 를 거치지 않으므로 100% 확정적**이고
   토큰도 쓰지 않습니다. `{CL:3}…{CL:0}` 같은 코드가 든 용어도 구조 그대로 유지됩니다.
3. **프롬프트 지시** — 마커가 안 붙은 용어(SOFT/HINT)는 기계 치환하면 조사·성수·
   어순이 깨지므로 바꾸지 않습니다. 대신 **그 배치에 실제로 등장하는 용어만** 뽑아
   "이 번역을 쓰라"는 표를 프롬프트에 붙입니다. 용어집이 8천 줄이어도 매 요청이
   커지지 않습니다.

```
시트 원본     베넘 나이프를 획득했다
 ①마커        «T:베넘 나이프»를 획득했다      ← 입력 열에도 이렇게 기입됩니다
 전송         «T:1»를 획득했다                (내부를 가려서 보냄)
 응답         Obtuviste «T:1»
 ②확정 치환   Obtuviste «T:Cuchillo Venenoso» ← 결과열. 마커는 사람이 직접 뗍니다
```

용어집에 없는 용어는 원문을 그대로 둡니다(기존 동작과 동일). 실행이 끝나면
**용어집에 없던 항목 목록**을 로그에 남기므로, 무엇을 채워야 할지 알 수 있습니다.

### 용어집 시트 구조

열은 **이름으로 찾으므로 순서는 상관없고, 모르는 열이 섞여 있어도 됩니다.**

| 열 | 필수 | 설명 |
|---|---|---|
| `ko-KR` | ✅ | 매칭 열쇠 (한국어 원문) |
| `en-US` `zh-CN` `th-TH` `es-ES` `de-DE` `fr-FR` `id-ID` `tr-TR` `pt-BR` `es-419` | | 언어별 용어. 빈 칸이면 그 언어에선 원문 유지 |
| `aliases` | | `|` 로 구분한 이형 표기 (조사 변형, 영어 표기 등) |
| `match_mode` | | `exact` / `exact_or_contains` / `boundary_only` |
| `protect_level` | | `HARD`(반드시) / `SOFT`(권장) / `HINT`(참고) |
| `priority` | | 숫자. 용어가 겹칠 때 큰 쪽이 이김 |
| `status` | | `active` 가 아닌 행은 무시 |
| `category` `term_key` `note` | | 참고용 |

- `match_mode` 는 문장 속 용어를 찾을 때 쓰입니다. `boundary_only` 는 단어 경계에서만
  잡아 짧은 용어(`검`, `가면`)가 다른 단어 안쪽에서 오탐되는 것을 막습니다.
- `protect_level` 은 프롬프트 문구를 정합니다 — HARD 는 "반드시", SOFT 는
  "활용·성수 변화 허용", HINT 는 "참고만".
- 대상 언어 값에 길리메(`«` `»`)가 들어있으면 토큰 구조가 깨지므로 **치환하지 않고**
  원문을 유지합니다(로그에 남습니다).

## 결과열 머리글

여러 언어를 한 시트에 붙이면 F/H/J/L… 중 어느 열이 무슨 언어인지 알 수 없습니다.
그래서 **데이터 시작 행 바로 위(보통 1행)에 로케일 표기를 자동으로 적습니다.**

```
        D        E              F        G              H        I
 1행    ko-KR                   en-US    en-US 특이사항   zh-CN    zh-CN 특이사항
 2행    …        …              …        …              …        …
```

- 직접 적어 두신 머리글(`원본(KR)`, `우리팀 영어열` 등)은 **덮지 않습니다.**
  빈 칸이거나 도구가 적었던 값일 때만 기입합니다.
- 시작 행이 1행이면(머리글 자리가 없으면) 아무 것도 쓰지 않습니다.
- 설정(⚙)의 `WRITE_HEADER` 로 끌 수 있습니다.

### 자동 업데이트
새 버전이 릴리스되면 실행 시 팝업으로 안내합니다. **예**를 누르면 새 exe 를
내려받아 자동으로 교체·재시작합니다. 편집한 프롬프트는 보존됩니다.

교체 과정은 exe 옆 `update.log` 에 기록됩니다. 업데이트가 이상하게 끝났다면
이 파일을 확인하세요. `_update_download.exe` / `RO_Translator.exe.old` 같은
찌꺼기 파일은 다음 실행 때 자동으로 지워집니다.

## «T:...» 마커는 결과에 그대로 남습니다

번역 대상 텍스트의 `«T:내용»` 마커는 **번역 결과에도 마커째로 남습니다.**
도구는 마커를 떼지 않습니다 — 떼는 작업은 번역이 끝난 뒤 사람이 눈으로 확인하며
직접 합니다.

도구가 보장하는 것:

| 단계 | 동작 |
|---|---|
| 부착 | 용어집 용어가 문장 속에 그냥 있으면 `«T:용어»` 로 감쌈. 표기가 완전히 같으면 등급 무관, 부분 일치는 HARD 만 (용어집 사용 시) |
| 전송 | `«T:내용»` → `«T:1»` 로 가려서 보냄 (모델이 내부를 번역·축약하지 못하게) |
| 복원 | 응답의 `«T:1»` → `«T:내용»` 으로 되돌림 |
| 용어집 | 마커 **안쪽 내용만** 대상 언어 공식 용어로 교체 (`«T:파란 포션»` → `«T:Poción azul»`). 마커는 그대로 |
| 검증 | 원본과 결과의 토큰(`«T:...»`, `{CL:n}`) 개수·내용이 정확히 같은지 대조 |
| 복구 | 모델이 훼손했으면 코드가 먼저 되돌리고, 안 되면 재번역 요청 |
| 표시 | 그래도 안 맞으면 특이사항열에 `플레이스홀더 불일치` |

검증 기준 열은 **번역 대상(플레이스홀더 역할) 열**이 1순위, 그 역할을 지정하지
않았으면 **원본 열**입니다. 즉 열 역할을 어떻게 설정하든 마커 보존은 검증됩니다.
(v1.8.0 이전에는 '플레이스홀더' 역할을 지정하지 않으면 마스킹·검증·복구가 통째로
꺼져서, 모델이 마커를 지워도 그대로 시트에 기입됐습니다)

### 표시된 행만 다시 번역하기 — 🧹 버튼 (v1.10.0)

**다시 번역할 행은 오직 '결과열이 비어 있는가' 로만 정해집니다.** 특이사항열은
표시만 할 뿐 대상 선정에 쓰이지 않습니다. 그래서 `플레이스홀더 불일치` 가 적힌
행을 다시 돌리려면 그 행의 **결과열을 손으로 비워야** 했습니다.

상단 **🧹** 버튼이 그 손작업을 대신합니다.

1. 특이사항열에 **도구가 자동으로 적은 표시**(`플레이스홀더 불일치`, `한글 포함`)가
   있는 행을 찾습니다
2. 몇 행이 걸렸는지 언어별로 보여주고 확인을 받습니다
3. 확인하면 그 행들의 **결과열 값만** 지웁니다 → 다음 실행에서 다시 번역됩니다

- **직접 적으신 메모가 있는 행은 건드리지 않습니다.** 도구가 적은 문구와 정확히
  같은 값일 때만 대상이 됩니다 (몇 행을 건너뛰었는지는 로그에 남습니다).
- **특이사항 표시는 지우지 않습니다.** 재번역이 정상으로 끝나면 그때 자동으로
  지워집니다. 중간에 멈춰도 무엇이 문제였는지가 시트에 남습니다.
- 연속 번역 계획에 켜진 언어가 둘 이상이면 **계획 전체 / 지금 언어만** 중에
  고를 수 있습니다.
- 흩어진 행을 비우면 연속된 행끼리만 한 요청으로 묶이므로(구멍 그룹) 요청 수가
  늘어납니다. 로그의 배치 수로 확인하실 수 있습니다.

## 문제 해결

### 업데이트할 때 "[WinError 5] 액세스가 거부되었습니다 ... _update_download.exe.part" 가 뜬다
새 exe 는 `_update_download.exe.part` 로 받은 뒤 이름을 바꿔 쓰는데, **그 이름 바꾸기가
막힌 것**입니다. 권한이 없다기보다 대개 다음 둘 중 하나입니다.

- 방금 받은 exe 를 **백신 실시간 검사가 잠깐 붙잡고 있음** (다운로드·바탕화면 폴더에서 특히 잦음)
- 지난 번 업데이트가 남긴 `_update_download.exe` 가 아직 물려 있음

v1.9.1 부터는 도구가 스스로 20초까지 재시도하고, 그래도 안 되면 다른 이름으로
저장해 업데이트를 이어갑니다. 그 전 버전에서 이 창을 만나면:

1. 잠시 후 🔄 버튼으로 다시 시도 (대개 성공합니다)
2. exe 옆의 `_update_download.exe*` 파일을 지우고 다시 시도
3. 프로그램을 다운로드 폴더가 아닌 **별도 폴더**(예: `C:\RO_Translator`)에 두고 실행
4. 그래도 안 되면 릴리스 페이지에서 `RO_Translator.exe` 를 직접 받아 덮어쓰기

교체 과정은 exe 옆 `update.log` 에 남으므로, 반복되면 이 파일을 확인하세요.

### "오디널(ordinal) 380을(를) DLL ...에서 찾을 수 없습니다" 창이 뜬다 (v1.7.0 이하)
v1.7.0 까지는 exe 안에 **빌드 서버(Windows Server 2025)의 Windows 런타임 DLL**
(`ucrtbase.dll`, `api-ms-win-*.dll` 44개)이 같이 들어 있었습니다. 이 DLL 들은
Windows 10 부터 OS 구성요소라 PC 마다 빌드 번호가 다른데, exe 가 실행할 때
풀어놓은 쪽이 시스템 폴더보다 먼저 검색돼 **서로 다른 빌드의 런타임이 한
프로세스에 섞이는** 상황이 생겼습니다. 어느 쪽이 먼저 잡히는지는 그때그때
달라서, '처음엔 창이 뜨고 다시 실행하면 멀쩡한' 증상으로 나타납니다.

**v1.8.0 부터는 이 DLL 들을 번들에서 빼고 OS 것을 쓰므로 증상이 사라집니다.**
(Windows 10 이상 필요 — Windows 10/11 에는 항상 들어 있는 런타임입니다)

- 아직 v1.7.0 을 쓰고 있다면: 창의 **확인**을 누르고 다시 실행한 뒤,
  업데이트 안내에서 **예**를 눌러 v1.8.0 으로 올리면 됩니다.
- v1.7.0 → v1.8.0 교체는 구버전의 옛 방식으로 진행되므로 교체 직후 한 번은
  창이 뜰 수 있습니다. 그 다음 실행부터는 뜨지 않습니다.

## 개발자용 — 빌드 & 배포

### 로컬 실행 (개발)
```bash
pip install -r requirements.txt
python main_ui.py          # 또는 run_ui.bat (전용 프로필 Chrome 자동 기동)
```
개발(.py) 모드에서는 자동 exe 교체가 동작하지 않습니다(코드는 git pull 로 갱신).

### 로컬 exe 빌드
```bash
pip install -r requirements.txt pyinstaller
pyinstaller RO_Translator.spec
# 결과: dist/RO_Translator.exe
```

### 릴리스 (자동 빌드)
```bash
python make_version.py 1.0.1     # version.txt 갱신
git add -A && git commit -m "release v1.0.1"
git push origin main
```
`main` 에 푸시하면 GitHub Actions(`.github/workflows/release.yml`)가 Windows 에서
exe 를 빌드하고 `version.txt` 버전(`v1.0.1`)으로 릴리스에 `RO_Translator.exe` 를
첨부합니다. (Actions 탭에서 **Run workflow** 로 수동 실행도 가능)
사용자는 다음 실행 때 자동 업데이트를 안내받습니다.

## 파일 구성
| 파일 | 역할 |
|------|------|
| `main.py` | 번역 엔진(시트 R/W, 배치, 응답 파싱, 행 ID 매칭, 프롬프트 시드) |
| `main_ui.py` | customtkinter 데스크톱 UI + 자동 업데이트 |
| `paths.py` | 개발/exe 환경별 경로(app_dir / resource_dir) |
| `updater.py` | GitHub Releases 기반 exe 자동 업데이트 |
| `config.py` | 설정 기본값(정본은 `settings.json`) |
| `glossary.py` | 용어집 로딩·매칭 + 플레이스홀더 확정 치환 |
| `prompts/_known_defaults.json` | 과거 배포 프롬프트 해시 — 편집 안 한 옛 파일을 갱신하는 기준 |
| `tools/make_prompt_baseline.py` | 위 해시표 생성 (`make_version.py` 가 배포 시 자동 실행) |
| `prompts/` | 언어별 번역 프롬프트(행 ID 규칙은 코드가 런타임 주입) |
| `make_version.py` | 배포자용 버전/태그 도구 |
| `RO_Translator.spec` | PyInstaller 빌드 정의 |
| `.github/workflows/release.yml` | 태그 푸시 시 exe 빌드·릴리스 |

`credentials.json` / `settings.json` 은 사용자 고유 파일이라 repo 에 포함하지 않습니다.
